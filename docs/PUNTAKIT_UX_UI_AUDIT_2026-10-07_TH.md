## 1. สรุปผู้บริหาร

ปัญหาหลักที่รายงานเมื่อ 2026-10-02 **ปิดแล้ว** รายงานนั้นพบว่าแอปมี "สองระบบดีไซน์อยู่ด้วยกัน" คือ
คลาส Tailwind ของพาเลตต์สีน้ำเงิน/กรมท่าที่เลิกใช้แล้ว (`slate-*`, `blue-*`, `gray-*`) ตัวอักษร 10–11px
ค่า hex ที่ฝังตาย และหน้าที่พังในโหมดมืด ปัจจุบัน:

- ค้นหาคลาสพาเลตต์ดิบทั่ว `client/src/**/*.tsx` → **ไม่พบเลย**
- ค่า hex ที่ยังฝังในโค้ดแอป → **4 ไฟล์ / 8 ค่า** (บรรทัดละ 2 ค่า) เป็นสีดำ-ขาวกลางหรือสีโทเคนของธีม
  (`Members.tsx:286`, `Attendance.tsx:279`, `member/MemberHome.tsx:96`, `ThemeContext.tsx:45`)
- ตัวอักษรจริงที่เล็กกว่า 12px → ไม่มีในหน้าจอใด (เหลือเฉพาะใน `ui/calendar.tsx` ของ shadcn ที่ไม่ได้ใช้)
- พื้นที่กดขั้นต่ำ 44px, วงแหวนโฟกัส `:focus-visible`, ลิงก์ข้ามไปเนื้อหาหลัก, การล็อกโฟกัสใน `Modal`
  และในลิ้นชักเมนูมือถือ, `StatusChip` ที่ไม่สื่อสถานะด้วยสีอย่างเดียว และวินัยการแยกสเกเลตันกับสปินเนอร์
  ล้วนมีอยู่แล้ว และถูกล็อกไว้ด้วยเทสต์ `client/src/ux-audit-regressions.test.ts`,
  `design-system-consistency.test.ts` และ `design-tokens.test.ts`

สิ่งที่เหลืออยู่เป็นปัญหาคนละกลุ่ม และกระจุกอยู่ 4 จุด:

1. **โหมดมืดย้ายโทเคนไปได้แค่ครึ่งทาง** `--color-success` / `--color-warning` / `--color-error`
   ไม่ถูก remap ใน `.dark` เลย ทำให้ป้ายสถานะทุกอันในแอปไม่ผ่านเกณฑ์ WCAG AA **ทั้งสองโหมด**
   (คำนวณได้ **3.08:1 – 4.51:1**) ตัวอักษรขาวบนพื้น success/warning ก็ไม่ผ่านเช่นกัน และ
   `/privacy` กับ `/terms` มองไม่เห็นในโหมดมืด (คำนวณได้ **1.04:1**) เพราะยังใช้ alias เก่า
   `--navy` / `--muted`
2. **เชลล์มีช่องโหว่ด้านคีย์บอร์ด/เทคโนโลยีสิ่งอำนวยความสะดวก 2 จุด** แก้ไม่ยาก: ลิ้นชักเมนูมือถือ
   **ตอนปิด** ยังอยู่ในลำดับการกด Tab และยังอยู่ใน accessibility tree และการเปลี่ยนหน้าแบบ lazy
   จะรื้อเชลล์ทั้งอันแล้วทำให้โฟกัสตกไปที่ `<body>`
3. **ตัวเลขและรายการที่ผู้ใช้ถูกขอให้เชื่อ ไม่จริงเสมอ** หน้าเช็คชื่อแสดง KPI `5 รอบ/สัปดาห์` ที่ฝังตาย
   และไม่มี API ใดคืนค่า; "กิจกรรมที่กำลังจะมาถึง" บนหน้าแรกคือ 3 กิจกรรมที่วัน **เก่าที่สุด** ตลอดกาล;
   ตัวกรองพื้นที่ในหน้าสมาชิกสร้างจาก 15 แถวของหน้าปัจจุบัน; และ CSV ของกลุ่มเพิกเฉยต่อช่วงวันที่
   ที่การส่งออกอีกสามรายการใช้อยู่
4. **บางหน้าสัญญาเกินกว่าที่ทำได้จริง** ป๊อปอัปคำขออธิษฐานสัญญาว่าจะมีทีมศิษยาภิบาลอธิษฐานเผื่อ
   แต่ไม่มีหน้าจอใดอ่านคำขอนั้นเลย; ข้อมูลนำเข้าที่มีแต่สื่อ (ไม่มีข้อความ) ต้องอนุมัติแบบมองไม่เห็น;
   เรื่องราวที่เผยแพร่ในฟีดถูกตัดเหลือ 2 บรรทัดและเปิดอ่านเต็มไม่ได้

- `Attendance.tsx` ต้องไม่มีตัวเลขลอย ๆ ในบล็อกสถิติ — เป็นการกัน KPI ที่กุขึ้นกลับมาแบบถูกที่สุด
- มีนิยาม `formatDate` / `formatDateTime` ที่เดียวใน `client/src/lib/` และไม่มีใน `client/src/pages/`

การเพิ่มตัวช่วยคำนวณคอนทราสต์ใน `design-tokens.test.ts` (มี `luminance()` + `contrast()` อยู่แล้วสำหรับคู่
primary) จะทำให้โทนของ `StatusChip` และพื้นสีสถานะถูกตรวจด้วยเทสต์แทนการดูด้วยตา

## 11. สิ่งที่การตรวจครั้งนี้ยืนยันไม่ได้

การตรวจครั้งนี้ไม่มีเบราว์เซอร์และไม่มีอุปกรณ์จริง ข้อต่อไปนี้ต้องทดสอบในสภาพแวดล้อมจริงก่อนจะถือว่าแก้เสร็จ

- **พิกเซลที่ตารางสมาชิกเริ่มถูกตัด** (M-1) กลไกยืนยันจากโค้ดแล้ว แต่จุดตัดจริงต้องดูภาพที่ 768px และ 1024px
- **เสียงจริงของโปรแกรมอ่านหน้าจอ** สำหรับลิ้นชักตอนปิด (S-1), ชื่อ landmark ของเมนู (S-3) และการย้ายโฟกัส
  ใน Modal — แอตทริบิวต์ยืนยันแล้ว แต่ผลที่อ่านออกเสียงยังไม่ได้ยืนยัน
- **iOS และ Android ในแอปสมาชิก**: คีย์บอร์ดทับป๊อปอัปคำขออธิษฐาน, `env(safe-area-inset-bottom)` กับแถบ
  home indicator, การชวนติดตั้งบน iOS (`beforeinstallprompt` ไม่ทำงานใน WebKit และ
  `isInstallPromptAvailable()` พึ่งเหตุการณ์นั้น) และการเปิดหน้าแบบออฟไลน์ไปยังเส้นทางที่ไม่เคยเข้าถึง
- **คอนทราสต์ของโทนสถานะบนพื้นโหมดมืดจริง** — อัตราส่วนคำนวณจากโทเคน แต่พื้นโหมดมืดมีการซ้อนสี
  (`--color-black` ที่ `#root` และการ์ด `#2a2a2c`)
- **การตัดบรรทัดภาษาไทยกับฟอนต์ Prompt** ที่ 390px โดยเฉพาะใน `line-clamp` และเซลล์ `whitespace-nowrap`
  (M-1, P-3)
- **service worker หลังการดีพลอย**: ว่าไม่มีเชลล์ที่แคชไว้ชี้ไปยังไฟล์ asset ที่ถูกลบจากแคชแล้ว
- **ปริมาณข้อมูลจริง**: ตารางสมาชิก, ตัวเลือกสมาชิกในหน้ากลุ่ม (M-2) และรายการกล่องข้อมูลนำเข้า
  ที่มีหลายร้อยแถวบนมือ Android ระดับกลาง
- **การเข้าสู่ระบบ/ออกจากระบบของ Clerk และพฤติกรรมตามบทบาทกับบัญชีจริง** — การตรวจครั้งนี้ใช้การอ่านซอร์ส
  และเทสต์เส้นทาง API ที่มีอยู่เท่านั้น
