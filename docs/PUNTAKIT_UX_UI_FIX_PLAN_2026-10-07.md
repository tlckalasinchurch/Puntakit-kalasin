## 4. PR-1 — โหมดมืดและคอนทราสต์ (C-1, C-2, C-3, C-4, C-5, C-7, X-3)

### 4.1 กลยุทธ์: เพิ่มโทเคนใหม่ ไม่แก้ค่าโทเคนเดิม

การเปลี่ยนค่า `--color-success` / `--color-warning` / `--color-error` โดยตรงจะกระทบ **ทุกจุดที่ใช้สีเหล่านี้**
(ตรวจแล้วพบการใช้ใน 19 ไฟล์ ทั้งป้าย ไอคอน พื้นปุ่ม และกราฟ) ความเสี่ยงสูงโดยไม่จำเป็น

ทางที่ปลอดภัยกว่า: **เพิ่มโทเคน "สีตัวอักษรบนพื้นโทน" แยกออกมา** แล้วให้เฉพาะ `StatusChip` ใช้โทเคนใหม่
ส่วนโทเคนเดิมยังใช้กับไอคอนและพื้นปุ่มเหมือนเดิม → ไม่กระทบหน้าจออื่นเลย

ค่าที่คำนวณแล้วผ่านเกณฑ์ 4.5:1 (ข้อความ 12px บนพื้นโทนเดียวกันที่ความจุ 10%):

| โทเคนใหม่                          | โหมดสว่าง (บนพื้นขาว)                      | โหมดมืด (บนพื้น `#2a2a2c`)    |
| ---------------------------------- | ------------------------------------------ | ----------------------------- |
| `--color-success-strong`           | `#157a4c` → **4.67:1**                     | `#6fce9b` → **6.10:1**        |
| `--color-warning-strong`           | `#9a5b12` → **4.73:1**                     | `#e8b06a` → **6.03:1**        |
| `--color-error-strong`             | `#b02a3c` → **5.52:1**                     | `#ef8a99` → **5.03:1**        |
| `--color-info-strong` (มีอยู่แล้ว) | เปลี่ยน `#2f72bf` → `#2a63a8` → **5.28:1** | คงเดิม `#8ab6ef` → **5.62:1** |

หมายเหตุ: `#2f72bf` อยู่ในรายการ hex ที่ `design-tokens.test.ts` ขึ้นทะเบียนว่า "พาเลตต์เก่าที่เลิกใช้"
(อนุญาตเฉพาะบรรทัดที่ประกาศ) การเปลี่ยนเป็น `#2a63a8` จึงเป็นการเก็บกวาดครั้งสุดท้ายไปด้วย

### 4.2 ขั้นตอนแก้

1. **`client/src/index.css`**
   - เพิ่ม 3 โทเคน `*-strong` ใน `:root` ตามตารางข้างบน (วางต่อจาก `--color-info-strong` บรรทัด 49)
   - เพิ่มการ remap ทั้ง 4 โทเคนในบล็อก `.dark` (บรรทัด 1123-1161) — บล็อกนี้ยังไม่มีการ remap
     `--color-success/--color-warning/--color-error` เลย จึงต้องเพิ่ม `*-strong` ให้ครบ

   - ลบ `--muted` ที่ประกาศซ้ำใน `:root` (บรรทัด 87) ให้เหลือความหมายเดียว (C-3)

3. **`client/src/pages/Attendance.tsx`** (บรรทัด 114-150) — สถานะที่ถูกกด (C-2)
   - **แนวทางที่แนะนำ:** เปลี่ยนจากพื้นทึบเป็น "พื้นโทน + เส้นขอบ + ตัวอักษรเข้ม + เครื่องหมายถูก"

## 5. PR-2 — เชลล์ การนำทาง และโฟกัส (S-1, S-2, S-3, S-4, S-6, S-7)

### 5.1 S-1 ลิ้นชักเมนูตอนปิด — ต้องระวัง breakpoint ให้ตรง

**กับดักสำคัญ:** ห้ามใส่ `inert={!open}` ตรง ๆ เพราะบนเดสก์ท็อป (`lg` ขึ้นไป) ลิ้นชักถูกแสดงถาวรด้วย
`lg:static lg:translate-x-0` และ `open` จะเป็น `false` เสมอ → ใส่ `inert` แบบไม่ดู breakpoint
จะทำให้ **เมนูหลักบนเดสก์ท็อปใช้งานไม่ได้ทั้งแถบ**

และ **ห้ามใช้ `useIsMobile()` ที่มีอยู่** (`client/src/hooks/useMobile.tsx` ใช้ breakpoint 768px)
เพราะแถบข้างใช้ `lg` = 1024px — ช่วง 768–1023px (iPad) จะไม่ถูกจัดการ

**ขั้นตอน**

1. เพิ่มฮุกใหม่ใน `client/src/hooks/useMobile.tsx` (ไฟล์เดิม) เช่น
   `useIsDesktop()` ที่ใช้ `window.matchMedia("(min-width: 1024px)")` ให้ตรงกับ `lg` ของ Tailwind
2. ใน `Sidebar.tsx` (บรรทัด 224-234): `const drawerOffCanvas = !isDesktop && !open;`
   แล้วใส่ `inert={drawerOffCanvas || undefined}` ที่ `<aside>`
   (`inert` ตัดทั้ง tab order และ accessibility tree พร้อมกัน จึงไม่ต้องใส่ `aria-hidden` ซ้ำ)
3. คงพฤติกรรมเดิมไว้ทั้งหมด: focus trap / Escape / scroll lock / คืนโฟกัส (`Sidebar.tsx:155-197`) ห้ามแก้
4. ทางเลือกที่ไม่ใช้ JS: เพิ่มคลาส `invisible lg:visible` เมื่อปิด — ง่ายกว่าแต่การเลื่อนปิดจะหายแอนิเมชัน
   (แนะนำให้ใช้ `inert` + ฮุก เพื่อรักษาแอนิเมชันเดิม)

## 15. เกณฑ์ "เสร็จ" และตัวชี้วัด

**Definition of Done ระดับโครงการ (เมื่อจบทั้ง 7 PR)**

1. ข้อบกพร่องระดับ **P1 ทั้ง 17 ข้อ** ปิดครบ และมีเทสต์กันถดถอยอย่างน้อยหนึ่งข้อต่อข้อ
2. `pnpm check` + `pnpm test` เขียว และจำนวนเทสต์เพิ่มขึ้นจาก 506 ตามงานที่ทำ
3. `brand-spec.md` / `design.md` สอดคล้องกับโทเคนจริง (บังคับโดยเทสต์ที่มีอยู่แล้ว)
4. ไม่มีคลาสพาเลตต์ดิบ ไม่มี `text-white` บนพื้น primary และไม่มีค่า hex ใหม่ในคอมโพเนนต์
5. CI เขียวบน PR ทุกอัน และไม่มีข้อบกพร่องใหม่ที่พบระหว่างทางถูกทิ้งไว้โดยไม่บันทึกในรายงาน
