# ADR 001: โหมดมืดเป็น token remap ไม่ใช่ class override

- **Status:** accepted
- **Date:** 2026-10-07 (บันทึกย้อนหลังจากการตัดสินใจที่มีอยู่แล้วในโค้ด)
- **Deciders:** เจ้าของโปรเจกต์
- **Supersedes:** —

## Context

แอปมีทั้งโหมดสว่างและโหมดมืด โดยโหมดมืดถูกสลับจากในแอป (ไม่ใช่ตาม `prefers-color-scheme`) และใช้คลาส `.dark` บน `documentElement`

แนวทางแรกที่เคยใช้คือ เขียนกฎ override เจาะจงคลาสของ Tailwind ด้วย `!important` เช่น
`.dark .text-slate-800 { … !important }`, `.dark .bg-white { … !important }`

วิธีนี้ **พังเงียบ ๆ**: มันครอบเฉพาะชื่อคลาสที่ใครสักคนนึกออกว่าจะต้องใส่ในลิสต์ ทุกหน้าจอใหม่ที่ใช้คลาส palette ดิบจะแสดงผลผิดในโหมดมืดโดยไม่มีอะไรเตือน และรายการ override ก็ต้องถูกต่อเพิ่มด้วยมือตลอดไป

## Decision

โหมดมืดคือ **การ remap CSS custom property** ที่บล็อก `.dark` ใน `client/src/index.css` เท่านั้น
ทุกสีในแอปต้องมาจาก `var(--color-*)` หรือคลาสจาก `components/DesignSystem.tsx`
**ห้าม**ใช้กฎ `.dark .<palette-class> !important` อีก

## Consequences

**ดี**
- หน้าจอใหม่ "ได้โหมดมืดฟรี" ตราบใดที่ใช้ token — ไม่ต้องแก้ CSS เพิ่มแม้แต่บรรทัดเดียว
- จำนวนที่ต้องดูแลคงที่ (ชุด token) ไม่โตตามจำนวนหน้า
- บังคับใช้ได้ด้วยเครื่อง: `client/src/design-system-consistency.test.ts` ล้มทันทีถ้ามีคลาส palette ในไฟล์แอป หรือมี override ด้วย `!important`
- บังคับว่าทุกสีต้องเป็น semantic → เปลี่ยนแบรนด์ได้โดยแก้ที่ token ที่เดียว

**แย่**
- **ห้ามใช้คลาส palette ของ Tailwind ในไฟล์แอปเลย** (`bg-blue-600`, `text-slate-500`) — เป็นข้อจำกัดที่นักพัฒนาใหม่จะชนทุกครั้ง และ error ที่ได้ (หน้าจอสีเพี้ยนในโหมดมืด) ไม่ปรากฏตอน build
- `components/ui/**` (shadcn primitive ซึ่งถูก generate) ยังใช้ token ชุดของ shadcn เอง (`--background`, `--border`) ⇒ มี **สองชุดชื่อ** ที่ต้อง bridge กันผ่าน `@theme inline` — เพิ่มความซับซ้อนในการอ่าน
- ต้องมีวินัย: การเพิ่ม token ใหม่ต้องเพิ่มทั้ง `:root` และ `.dark` ไม่งั้นค่าจะค้างจากโหมดสว่าง (นี่คือสาเหตุที่สี status ทั้ง 4 ไม่ถูก remap — ดู deviation ใน `DESIGN_SYSTEM.md` §3.2)

**เป็นกลาง**
- ต้องมี `@custom-variant dark (&:is(.dark *))` เพื่อให้ variant `dark:` ของ Tailwind ทำงานกับคลาสที่เราสลับเอง

## Alternatives considered

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| override คลาส palette ด้วย `!important` | พังเงียบ ๆ กับหน้าใหม่ทุกหน้า และรายการต้องโตด้วยมือ — คือสิ่งที่ ADR นี้แทนที่ |
| แยก stylesheet สองชุด (light.css / dark.css) | ซ้ำซ้อนทั้งไฟล์ และเสี่ยงที่สองชุดจะเพี้ยนจากกัน |
| บังคับโหมดมืดจาก `prefers-color-scheme` เท่านั้น (ไม่ให้ผู้ใช้สลับ) | ผู้ใช้ในคริสตจักรต้องการสลับเอง และตัวสลับอยู่ใน Topbar แล้ว |
| ใช้ CSS `light-dark()` | ยังต้องมี token อยู่ดี และ browser support/พฤติกรรมกับ Tailwind v4 ยังไม่คุ้มความเสี่ยง |
