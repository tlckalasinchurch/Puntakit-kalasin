# Puntakit — Wireframe หน้าเมนูและหน้าโปรไฟล์

เอกสารนี้เป็นโครงร่างแบบข้อความสำหรับหน้าจอมือถือขนาดประมาณ 390 × 844 px โดยออกแบบให้ Puntakit รู้สึกเป็นแอปชุมชนที่อบอุ่น ใช้งานง่าย และช่วยให้ผู้ใช้รู้ว่าควรทำอะไรต่อในแต่ละหน้าจอ

## หลักร่วมของทั้งสองหน้า

- พื้นหลังหลัก: `#FFF9EF` Warm Ivory
- พื้นผิวการ์ด: ขาว `#FFFFFF`
- สีข้อความหลัก: `#332820`
- สีข้อความรอง: `#75685D`
- มุมโค้งการ์ดหลัก: 22–28 px
- ปุ่มและพื้นที่กด: อย่างน้อย 44 × 44 px
- Bottom navigation ลอยอยู่ด้านล่างเหมือนหน้า Home
- ทุกหน้ามีจุดประสงค์เดียวอย่างชัดเจน
- ใช้ภาษาเรียบง่ายและหลีกเลี่ยงคำที่ให้ความรู้สึกเหมือนระบบราชการหรือ dashboard

# 1. Menu Layout — หน้าเมนู

## เป้าหมายของหน้า

ช่วยให้ผู้ใช้เข้าถึงสิ่งที่ทำบ่อยและการตั้งค่าของตนเองได้โดยไม่ต้องจำว่าฟีเจอร์อยู่ที่ไหน โดยหน้าเมนูไม่ควรเป็นเพียงรายการฟังก์ชันยาว ๆ แต่ควรตอบคำถามว่า **“ตอนนี้ฉันทำอะไรต่อได้บ้าง?”**

## รายละเอียดแต่ละส่วน

### 1. Top bar

- ด้านซ้าย: ปุ่มย้อนกลับ หากเข้าหน้าเมนูจากหน้าอื่น
- ชื่อหน้า: `เมนู`
- ด้านขวา: ปุ่มเพิ่มเติมหรือการแจ้งเตือนตามบริบท
- หากหน้าเมนูเปิดจาก bottom navigation โดยตรง สามารถตัดปุ่มย้อนกลับออกได้ และใช้เพียงชื่อหน้า

### 2. Header

ข้อความที่แนะนำ:

> **สิ่งที่คุณทำได้**  
> ทุกสิ่งที่ช่วยให้เราดูแลกันได้ดีขึ้น

คำว่า “สิ่งที่คุณทำได้” ทำให้ผู้ใช้รู้สึกว่าหน้านี้ช่วยให้ลงมือทำ ไม่ใช่แค่หน้ารวมการตั้งค่า

### 3. Featured action card

ใช้สี Soft Peach หรือ Soft Lavender เพื่อดึงความสนใจเพียงจุดเดียวในหน้า

ข้อความตัวอย่าง:

> **มีเรื่องราวจากสัปดาห์นี้ไหม?**  
> ใช้เวลาเพียง 2 นาทีเพื่อบันทึกสิ่งที่เกิดขึ้น

ปุ่มหลัก:

> **เริ่มรายงาน**

พฤติกรรม:

- กดทั้งการ์ดได้ ไม่จำเป็นต้องกดเฉพาะปุ่ม
- กดแล้วไปที่ flow รายงานพันธกิจ ขั้นตอนที่ 1
- เมื่อมีรายงานค้างอยู่ ให้เปลี่ยนข้อความเป็น `ทำรายงานต่อ` พร้อมระบุ `ขั้นตอนที่ 3 จาก 5`

### 4. กลุ่ม “ทำบ่อย”

ใช้การ์ด 2 คอลัมน์เพื่อให้เข้าถึงเร็วและใช้พื้นที่น้อย:

- รายงานพันธกิจ
- เพิ่มสมาชิก
- สร้างกิจกรรม ถ้าผู้ใช้มีสิทธิ์
- ดูการแจ้งเตือน ถ้ามีข้อมูลที่ต้องดำเนินการ

แต่ละการ์ดควรมี:

- ไอคอนเส้นบาง
- ชื่อไม่เกิน 2 บรรทัด
- คำอธิบายสั้นไม่เกิน 1 บรรทัด
- สี pastel ที่ต่างกันเล็กน้อย

### 5. กลุ่ม “ชุมชน”

ใช้ list card แนวตั้งแทน grid เพราะรายการเหล่านี้เป็นพื้นที่ที่ต้องอ่านคำอธิบายประกอบ:

| รายการ | คำอธิบาย | ปลายทาง |
|---|---|---|
| กลุ่มพันธกิจ | ดูกลุ่มและพื้นที่ของเรา | Ministry / Groups |
| กิจกรรมที่กำลังจะมาถึง | ค่าย นมัสการ และกลุ่มย่อย | Events |
| การดูแลสมาชิก | ติดตามและให้กำลังใจ | People / Follow-up |

### 6. กลุ่ม “บัญชีของฉัน”

แสดงข้อมูลผู้ใช้ขนาดเล็กเพื่อทำให้หน้านี้เป็นพื้นที่ส่วนตัว:

```text
[Avatar]  สมชาย ใจดี                 >
          สมาชิก · กลุ่มเมือง 1
```

ควรมีเพียงรายการสำคัญ:

- โปรไฟล์ของฉัน
- การตั้งค่า
- ความช่วยเหลือ

ไม่ควรวาง “ออกจากระบบ” เด่นเกินไป ควรอยู่ด้านล่างสุดของหน้า settings หรืออยู่ใน bottom sheet ยืนยันอีกครั้ง

## สถานะที่ควรรองรับ

### ผู้ใช้ใหม่

```text
ยังไม่มีกลุ่มพันธกิจ
เข้าร่วมกลุ่มแรกของคุณ เพื่อเริ่มเดินไปด้วยกัน
[ดูกลุ่มใกล้ฉัน]
```

### ฟีเจอร์ที่ยังไม่พร้อม

ไม่ควรทำให้ดูเหมือนกดได้ปกติ แนะนำใช้:

```text
รายงาน & สถิติ                         เร็ว ๆ นี้
ดูภาพรวมและความก้าวหน้า
```

หากกดได้ ให้เปิด toast หรือ bottom sheet ที่บอกชัดเจนว่าอยู่ระหว่างการพัฒนา

ทำให้ผู้ใช้รู้สึกว่า **“นี่คือพื้นที่ของฉันในชุมชน”** และสามารถตรวจสอบหรือแก้ไขข้อมูลพื้นฐานของตนเองได้ง่าย โดยไม่ทำให้หน้าโปรไฟล์ดูเหมือนแบบฟอร์มทะเบียนสมาชิก

## รายละเอียดแต่ละส่วน

### 1. Profile hero

ลำดับข้อมูล:

1. Avatar
2. ชื่อเต็ม
3. บทบาทและกลุ่ม
4. ข้อมูลเชิงความสัมพันธ์ เช่น “อยู่กับ Puntakit ตั้งแต่...”
5. ปุ่มแก้ไขโปรไฟล์

ตัวอย่าง:

> **สมชาย ใจดี**  
> สมาชิก · กลุ่มเมือง 1  
> อยู่กับ Puntakit ตั้งแต่ มกราคม 2024

ไม่ควรใช้ badge จำนวนมาก เช่น `ACTIVE`, `VERIFIED`, `ADMIN` เพราะจะทำให้หน้าดูเป็นระบบองค์กรเกินไป

### 2. ข้อมูลของฉัน

แสดงเป็น key-value list ที่อ่านง่าย ไม่ควรเปิดเป็น input ทั้งหมดทันที

```text
ชื่อ-นามสกุล       สมชาย ใจดี
เบอร์โทร           08x-xxx-xxx
กลุ่มพันธกิจ       กลุ่มเมือง 1
พื้นที่             เมืองกาฬสินธุ์
```

พฤติกรรม:

- แตะปุ่ม `แก้ไข` เพื่อเปิด edit mode
- บนมือถือควรใช้ bottom sheet หรือหน้าเต็มสำหรับแก้ไข
- ไม่ควรมีฟอร์มยาวที่แสดง input ทุกช่องตั้งแต่แรก

### 3. การมีส่วนร่วม

ส่วนนี้ทำให้โปรไฟล์มีความเป็นชุมชนมากกว่าบัญชีผู้ใช้ทั่วไป:

- **กลุ่มของฉัน** — ดูกลุ่มที่เข้าร่วมและหัวหน้ากลุ่ม
- **กิจกรรมที่กำลังจะมาถึง** — ดูสิ่งที่ลงทะเบียนหรือได้รับเชิญ
- **รายงานที่ฉันเคยส่ง** — ดูประวัติการมีส่วนร่วมของตนเอง

แต่ละรายการควรมีจำนวนหรือสถานะสั้น ๆ ทางด้านขวา และมี chevron เพื่อบอกว่ากดต่อได้

### 4. สถานะการดูแล

ควรแสดงอย่างระมัดระวังและมีคำอธิบายเสมอ:

```text
สถานะการดูแล
● มีการติดต่อแล้ว
สถานะนี้ใช้เพื่อช่วยทีมงานดูแลสมาชิก
ไม่ใช่การตัดสินคุณค่าหรือความเชื่อของคุณ
```

คำที่แนะนำ:

- มีการติดต่อแล้ว
- อยู่ระหว่างการดูแล
- ต้องการการติดตาม

คำที่ควรหลีกเลี่ยง:

- สุขภาพฝ่ายจิตวิญญาณ
- คะแนนสมาชิก
- อ่อนแอ
- ไม่กระตือรือร้น
- ความเสี่ยงสูง

## สถานะของหน้าโปรไฟล์

### กำลังโหลด

ใช้ skeleton ที่ตำแหน่ง avatar, ชื่อ และรายการข้อมูล แทน spinner ขนาดใหญ่กลางหน้า

### บันทึกสำเร็จ

แสดงข้อความสั้น ๆ:

> บันทึกข้อมูลแล้ว

พร้อม toast หรือ inline confirmation ที่ไม่บังเนื้อหาหลัก

### บันทึกไม่สำเร็จ

แสดงข้อความที่บอกทางแก้:

> บันทึกไม่สำเร็จ กรุณาตรวจสอบเบอร์โทรแล้วลองอีกครั้ง

ห้ามล้างข้อมูลที่ผู้ใช้กรอกไว้เมื่อเกิด error

### ผู้ใช้ยังไม่มีข้อมูลครบ

```text
ยังไม่มีข้อมูลกลุ่มพันธกิจ
เพิ่มกลุ่มของคุณ เพื่อให้ทีมงานดูแลและสื่อสารได้ง่ายขึ้น
[เพิ่มกลุ่ม]
```

# 3. การเชื่อมโยงระหว่าง Menu และ Profile

แนะนำให้ใช้เส้นทางการใช้งานดังนี้:

```text
Home
  └── Bottom nav: เมนู
        ├── การ์ด “รายงานพันธกิจ” → Weekly Report
        ├── “กลุ่มพันธกิจ” → Ministry / Groups
        ├── “การดูแลสมาชิก” → People / Follow-up
        └── “สมชาย ใจดี” → Profile
                                  ├── แก้ไขโปรไฟล์
                                  ├── กลุ่มของฉัน
                                  ├── กิจกรรมของฉัน
                                  └── การตั้งค่า
```

หลักสำคัญคือผู้ใช้ควรย้อนกลับได้ทุกหน้า และไม่ควรต้องกลับไปที่หน้า Menu เพื่อทำงานต่อเนื่องที่เกี่ยวข้องกัน

# 4. ลำดับความสำคัญของการพัฒนา

## รุ่นแรก

1. หน้าเมนูพร้อม featured action card
2. กลุ่ม “ทำบ่อย / ชุมชน / บัญชีของฉัน”
3. หน้าโปรไฟล์แบบอ่านอย่างเดียว
4. ปุ่มแก้ไขโปรไฟล์
5. สถานะ loading, success และ error

## รุ่นถัดไป

1. ปรับรายการเมนูตาม role ของผู้ใช้
2. เพิ่มกลุ่มของฉันและกิจกรรมของฉัน
3. เพิ่มการตั้งค่าการแจ้งเตือน
4. เพิ่ม privacy controls
5. เพิ่มประวัติการมีส่วนร่วมแบบย่อ

> **หลักการตัดสินใจสุดท้าย:** หน้าเมนูควรช่วยให้ผู้ใช้ “ลงมือทำ” ส่วนหน้าโปรไฟล์ควรช่วยให้ผู้ใช้รู้สึกว่า “ฉันมีที่อยู่ในชุมชนนี้”
